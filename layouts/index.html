One widget tree,
every surface.

A widget that calls the platform's own button is as portable as the least capable platform it targets. go-widgets draws every widget itself, through one small painter interface, and lets a back-end decide whether that becomes the pixels of a window, a browser canvas, an Android surface — or the cells of a terminal. Pure Go, CGO_ENABLED=0. BSD-3-Clause.

Why go-widgets

A widget never learns where it is drawn.

Its Draw talks to a painter: fill a rectangle, stroke one, set a pixel, draw text. Whether those calls become pixels or terminal cells is the back-end's business. That is the whole reason one widget tree runs in a native window, a browser and a terminal without a line of conditional code.

🖌️

Drawn by the toolkit, everywhere

No webview, no system widget set, no C toolchain. 160 widget types — a data suite with Table, Kanban, Gantt and an event calendar, eight charts, menus, dialogs — drawn the same way on every surface, tested once.

🧭

Chosen by what is there

window.Open takes no back-end argument. It reads the environment — the platform, $WAYLAND_DISPLAY, $DISPLAY, an Android host's socket — and opens the window that can work. The same Android binary dials its host inside an APK and opens a Linux window under Termux.

🔌

Without cgo, all the way down

X11 is the core protocol written from scratch over the socket. macOS is reached through the Objective-C runtime, Windows through the process's own DLLs, both from Go. Android, which hands no surface to a CGO-free process, gets a thin Java host that only blits.

🔁

State lives in a view-model

Observables, commands and lists, bound to widgets once. The core imports no widget package, so one view-model drives the pixel widgets and the terminal ones. mvvmlint fails a pull request that assigns a widget's field by hand.

♿

Accessibility it publishes itself

A toolkit that paints its own pixels gives a screen reader nothing — unless it says what it drew. Widgets report a role, a name and a value; the back-ends publish them: AT-SPI on Linux, a virtual view hierarchy on Android, pulled only when something reads it.

🔤

Text without a C library

One call switches the whole UI to anti-aliased, shaped text in a bundled face, rasterised by go-opentype in Go — no FreeType, no system font lookup, the same in a browser. GTK and libadwaita themes load as a Theme.

🎨

Widgets as data, when you want them

A skin describes a widget's parts, states and transitions in JSON, rendered by one engine. The toolkit's own button, switch and card, written as skins, render pixel for pixel the same.

🗂️

The same data, local or remote

A typed store queries an in-process proxy or a gRPC one over a WebSocket, and the conformance test requires the two to return byte-identical views — so a wasm client and a native one see the same rows.

⚖️

Proven on real displays

Pixels sampled from a real X11 server under Xvfb and from a macOS window in CI, clicks driven through a real Win32 window procedure on Windows 11, composited pixels read back from the wasmdesk compositor in Chromium, blits timed on an Android device. What is only compiled is said too.
